# Офлайн-обновление nginx и PHP в Docker

Комплект содержит два Linux-контейнера. nginx принимает HTTP-запросы и передаёт их Apache с PHP. По умолчанию используются nginx **1.30.8** и PHP **8.5.13**. При подготовке образов устанавливаются готовые бинарные пакеты из репозиториев nginx.org и Sury. Интернет нужен только машине, которая готовит комплект.

Комплект предназначен для серверов Linux x86‑64 (`linux/amd64`) с Docker Engine и Docker Compose v2. Один архив подходит для Debian, Ubuntu, Astra Linux, AlmaLinux и РЕД ОС, если Docker совместим с ядром хоста. Debian Trixie используется внутри образов.

## 1. Подготовьте комплект на машине с интернетом

Из корня проекта:

```bash
NGINX_VERSION=1.30.8 PHP_VERSION=8.5.13 RELEASE=r1 bash build.sh
```

Скрипт проверяет версии и конфигурацию сервисов при подготовке образов. В `work/` появятся архив `nginx1.30.8-php8.5.13-amd64-r1.tar.gz` и его `.sha256`. Внутри архива находятся образы, конфигурация по умолчанию и `images.env` с уникальными тегами. При следующем обновлении укажите версии с нужными исправлениями и новый `RELEASE`. Если версии приложения остались прежними, новая ревизия позволяет обновить бинарные пакеты и зависимости, сохранив предыдущие теги для отката.

В стандартном комплекте nginx доступны **GeoIP Legacy** и **Stream**. Для запросов GeoIP отдельно подключите нужную базу `.dat`. PageSpeed, Brotli, headers-more и mod_zip в стандартный комплект не входят. Если сайт использует эти модули, для переключения нужны готовые бинарные модули, совместимые с версией nginx в комплекте. Проверьте их загрузку командой `nginx -t` до переключения трафика.

## 2. Загрузите комплект на сервер

Для действующего Bitrix с настройками nginx и Apache на хосте используйте [отдельный шаблон Compose](containers/bitrix/README.md). Он входит в комплект в каталоге `bitrix/`.

Перенесите архив и его `.sha256` в постоянный каталог Compose, например `/opt/web-stack`. Выполните из этого каталога:

```bash
release=nginx1.30.8-php8.5.13-amd64-r1
mkdir -p releases &&
sha256sum -c "$release.tar.gz.sha256" &&
tar -xzf "$release.tar.gz" -C releases &&
docker load -i "releases/$release/images.tar"
```

При первом развёртывании скопируйте шаблоны в постоянный каталог. При обновлении используйте действующие конфиги и при необходимости сверяйте их с шаблонами нового комплекта.

```bash
cp -n "releases/$release/compose.yaml" .
cp -n "releases/$release/nginx.conf" .
```

Создайте рядом `site.env` и укажите существующий каталог сайта на сервере:

```dotenv
SITE_DIR=/srv/www/example
HTTP_BIND=127.0.0.1
HTTP_PORT=8080
```

По умолчанию nginx доступен локально на порту 8080. Это позволяет проверить новый стек рядом с работающим сайтом. В контейнере Apache сайт находится в `/var/www/html`. Сохраните права на его файлы и запись в используемые приложением каталоги. Перенесите нужные параметры PHP и виртуальных хостов Apache. Для внешнего трафика настройте действующий TLS-прокси на этот порт или подключите сертификаты и опубликуйте HTTPS в конфигурации Compose. В nginx адрес Apache внутри проекта — `php:80`. Для БД на хосте укажите адрес, доступный из контейнера, или подключите каталог с Unix-сокетом.

## 3. Запустите или обновите сервисы

Используйте постоянный каталог и одно и то же имя проекта Compose. Для нескольких независимых стеков задайте отдельные имена и порты.

```bash
docker compose -p web-stack --env-file site.env \
  --env-file "releases/$release/images.env" up -d --no-build --pull never
docker compose -p web-stack --env-file site.env \
  --env-file "releases/$release/images.env" ps
curl -I http://127.0.0.1:8080/
```

Перед переключением внешнего трафика проверьте нужный сайт с его заголовком `Host` и запрос, который обрабатывает PHP и обращается к БД. При обновлении Compose пересоздаёт изменившиеся контейнеры. Запланируйте короткое окно обслуживания, если сайт уже обслуживается этим стеком. На сервере не выполняются скачивание образов или установка пакетов. Сайты сохраняют доступ к БД и сетевым сервисам согласно конфигурации сервера.

## Откат

Храните предыдущий комплект и его `images.env`. Для отката укажите предыдущий релиз и выполните ту же команду с тем же именем проекта:

```bash
previous=nginx1.30.8-php8.5.13-amd64-r1
docker compose -p web-stack --env-file site.env \
  --env-file "releases/$previous/images.env" up -d --no-build --pull never
```

Если образы предыдущего релиза уже удалены из Docker, сначала загрузите их из `releases/$previous/images.tar`. При изменениях конфигурации сайта примените её предыдущую версию перед откатом.
